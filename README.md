# 精灵图裁切检查器（Spritesheet Inspector）

一个**完全离线**的单页工具，帮助定格动画合成师在没有元数据的 PNG 精灵图上，
通过填写行列数、四边距与帧间距，逐帧预览裁切结果并导出 JSON 清单，
避免“预览看似正常却漏裁一列”的事故。

- 技术栈：TypeScript + React 19 + Vite 8 + Canvas API
- 不发起任何网络请求：图片只在浏览器本地解码、裁切；产物为纯静态文件
- 单元测试：Vitest（坐标边界、整除、编号顺序、清单一致性）
- 端到端测试：Playwright（上传、解码失败、参数非法、行/列优先切换、清单下载）

## 页面参数含义

| 参数 | 取值 | 含义 |
| --- | --- | --- |
| 行数 `rows` | 正整数 ≥ 1 | 网格在垂直方向上的帧数 |
| 列数 `columns` | 正整数 ≥ 1 | 网格在水平方向上的帧数 |
| 上边距 `marginTop` | 非负整数（像素） | 图片上边缘到第一行帧上边缘的距离 |
| 右边距 `marginRight` | 非负整数（像素） | 最右列帧右边缘到图片右边缘的距离 |
| 下边距 `marginBottom` | 非负整数（像素） | 最末行帧下边缘到图片下边缘的距离 |
| 左边距 `marginLeft` | 非负整数（像素） | 图片左边缘到第一列帧左边缘的距离 |
| 水平帧间距 `gapX` | 非负整数（像素） | 相邻两列帧之间的空白宽度（列与列的间隙，只出现 `columns − 1` 次） |
| 垂直帧间距 `gapY` | 非负整数（像素） | 相邻两行帧之间的空白高度（行与行的间隙，只出现 `rows − 1` 次） |
| 编号顺序 | 行优先 / 列优先 | 见下文“编号规则” |

所有长度以**像素**为单位，且必须是整数；不接受小数、负数、空白或科学计数法。

### 有效区域公式

```
有效宽度 = 图片宽度 − 左边距 − 右边距 − (列数 − 1) × 水平帧间距
有效高度 = 图片高度 − 上边距 − 下边距 − (行数 − 1) × 垂直帧间距
```

约束（任一不满足都会报错并清空旧帧）：

1. 有效宽度、有效高度必须 **为正**；
2. 有效宽度必须能被**列数**整除，有效高度必须能被**行数**整除；
3. 帧宽 = 有效宽度 ÷ 列数，帧高 = 有效高度 ÷ 行数，取精确整数；
4. 每个帧矩形必须完整落在图片范围内（裁切越界即报错）。

### 坐标与裁切约定

- 坐标原点在**图片左上角**，x 向右、y 向下；
- 帧矩形为半开区间：**含左上边、不含右下边**，即像素列为 `[x, x+width)`，
  像素行为 `[y, y+height)`。因此最右列的 `x + width` 恰好等于
  “图片宽 − 右边距”是合法的，不算越界；
- 帧编号**从 1 开始**。

### 编号规则

设当前位置为第 `row` 行、第 `col` 列（均从 0 开始计）：

- **行优先（先列后行）**：先沿列方向数满一行再换行
  `index = row × columns + col + 1`
- **列优先（先行后列）**：先沿行方向数满一列再换列
  `index = col × rows + row + 1`

两种顺序只改变编号，不改变任何帧的裁切矩形；每个裁切区域有且只有一个编号。

第 `row` 行第 `col` 列帧的左上角为：

```
x = 左边距 + col × (帧宽 + 水平帧间距)
y = 上边距 + row × (帧高 + 垂直帧间距)
```

## 界面行为

- 合法时：逐帧显示**裁切图、编号、x、y、宽、高**，并在原图上叠加红色帧框与编号；
  可「下载 JSON 清单」（内嵌每帧 PNG data URL，内容与画面同源）；
- 参数非法、图片解码失败或裁切越界时：**立即清空旧帧**，错误原因显示在红色提示框中；
- 切换行/列优先：画面、总览与 JSON 清单同步更新，编号与裁切区域始终一一对应。

JSON 清单结构：`image`（文件名与原图尺寸）、`params`（全部输入参数与顺序）、
`frameWidth/frameHeight`、`frames[]`（按编号升序，含 `index/x/y/width/height/dataUrl`）。

## 本地开发

```bash
npm install
npm run dev          # 开发服务器（默认 http://127.0.0.1:5173）
npm run build        # 类型检查 + 产物输出到 dist/
npm run preview      # 本地预览生产产物（http://127.0.0.1:4173）
```

## 测试

```bash
npm run test:unit    # Vitest：解析校验、公式、整除、半开区间边界、两种编号
npm run test:e2e     # Playwright：自动起 vite preview 后跑上传/校验/切换/下载
npm run verify       # build + 单测 + e2e 一次性全跑（与 Docker verify 服务一致）
```

e2e 用内置 zlib 现场生成带边距/间距、每帧纯色的 PNG（`e2e/makePng.ts`），
并对裁切结果**逐像素采样**断言，不使用固定期望值。

## Docker（只运行静态 Web）

镜像为多阶段构建：构建阶段产出 `dist/`，最终 `web` 阶段只有 nginx 与静态文件，
不含 Node、源码或服务端逻辑。

```bash
docker compose up -d --build web
# 浏览器打开 http://localhost:8080
```

### WEB_PORT（宿主端口覆盖）

compose 把容器内 80 映射到宿主的 `${WEB_PORT:-8080}`：

```bash
WEB_PORT=9000 docker compose up -d web   # → http://localhost:9000
```

### verify 一次性验收服务

`verify` 是**一次性**服务（`docker compose run --rm verify`），在预装 Chromium 的
镜像中依次执行类型检查、Vitest 与 Playwright，退出码 0 表示验收通过；
它不会常驻，也不对外暴露端口：

```bash
docker compose build verify
docker compose run --rm verify
```
